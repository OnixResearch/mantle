# I6 source-bundle CLI effect boundary (2026-10-01)

Scope: `source bundle` plan, export, list, import, verify, preflight, bootstrap-profile, refresh-mantle-source, and hydrate-self-build. The source application contract admits a bounded, action-specific effect plan before the CLI calls the source port. The shell then supplies independently observed artifact formats, bytes, record counts, connected-fetch call counts, published bundle readback, imported records and pins, and vendor-tree readback to the shared classifier before printing a successful report. Network authority is absent unless export explicitly requests connected fetch; a connected export with zero actual fetch calls records zero calls and no network output artifact.

A source write alone is not completion: export, bootstrap-profile publication, and refresh require an exact published-manifest readback; import rechecks durable records and its requested pin, including replay; hydration resnapshots its published vendor tree and rechecks records and pin. Unknown, missing, duplicate, wrong-authority, wrong-output, wrong-unit, and over-limit evidence is rejected by the shared effect envelope. Rejection leaves the CLI's existing JSON/human reports and exit semantics unchanged when the source report is a genuine readiness failure. A successful source operation proves only the named bounded input/state observations; it does not prove source authenticity beyond admitted metadata, compiler correctness, build success, or release eligibility.
