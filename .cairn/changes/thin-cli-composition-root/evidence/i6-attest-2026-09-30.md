# I6 attestation CLI cutover (2026-09-30)

Scope: all 14 executable `mantle attest` actions (`show`, `closure`, `diff`, `project`, three `verify` targets, `release-show`, `release-verify`, `key-show`, `witness-create`, `witness-show`, `witness-import`, `policy-init`). This is **not** I6 completion evidence for the other CLI families.

The pure `mantle-application-contract::attest` planner admits one typed, operation-specific effect before starting the CLI runtime or opening a port. It binds the exact selected action/target, current directory, store/backend/base-state authority, optional configured signing/trust directory, output authority, and canonical result range (including zero results for empty witness lists). Hashing selected argument tuples without an intermediate serialization allocation bounds at most 1,024 selected inputs and 65,536 hashed argument bytes; returned entries are checked against the selected operation's limit (up to 2,048). The classifier independently checks the adapter's actual effect identity, capability, operation, target, authority, selected byte/input usage, output authority, result entries, and failure stage. It rejects contradictory observations, including wrong store, target, output, effect kind, configured directory, and over-limit results.

Store-backed queries use the honest composite `StoreAccess` capability: opening the selected store may initialize its state directory and identity, and closure lookup may persist a reconstructed attestation. Read-only release/witness lookups do not open the store. File publication may leave partial output on error; witness creation without an existing selected signing key can initialize the configured key. Returned entries do not prove optional writes, durable bytes, or signer/builder correctness. `key-show` observes the actual returned signing-key source path; publication observes returned output directories and receipt counts. The two signing-key selector helpers are `pub(crate)` only, with their previous bodies/creation/trust behavior unchanged; the backend Casita owner acknowledged those exact visibility-only changes.
