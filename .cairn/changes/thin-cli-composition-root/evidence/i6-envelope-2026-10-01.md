## Contract and adapters

`EffectSpec` identifies each effect independently of `EffectKind`, supplies one positive bound (`Calls`, `Items`, or `Bytes`) and its expected output identity. `plan_effects` returns typed errors for empty, duplicate, zero-bound, empty-output, and oversized declarations. `classify_observations` rejects unknown, duplicate, missing, wrong-authority, wrong-output, wrong-unit, and over-limit observations; failed/skipped actual work cannot become success. Deserialized/reconstructed malformed plans (including empty and zero-bound plans) cannot vacuously complete.

The graph query result's independently observed target and bounded fact counts are compared against the canonical target declared from the admitted graph **before** executing the query; this preserves aliases such as `gallery-output` while still rejecting observations for another target. Export classification distinguishes the artifact-store content source from materialized-file reads. Store administration uses distinct effect IDs per action (including GC plan versus execute), a closed planned authority mapping, and separately supplied observed authorities; unrecognized IDs fail closed. The main remote-import check uses one bounded store-access import observation and validates each imported output's actual evidence without allocating a second output list.

Shared cutover also updates the direct application callers in file generation, logging, project, release, source, pin/cargo import, and attestation under their respective owners; their separate evidence and root integration are required before claiming those surfaces complete.
