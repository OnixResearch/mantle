## Functional Core and Effect Shell

The functional core validates a bounded versioned case manifest and immutable observations, constructs deterministic cell/step identities, applies a narrowly versioned semantic comparison policy, and classifies outcomes. It performs no process execution, environment mutation, filesystem access, clock reads, or cache writes. Reuse existing Rust-plan identity types where the roles match; the report remains diagnostic evidence, not an execution admission receipt or PathInfo authority.

The shell materializes exact source snapshots; measures executable/sysroot/tool closures; launches existing supported commands with explicit child environments; captures bounded raw streams; applies exact declared edits; probes capabilities; executes successful build outputs; controls process trees; and inspects only the attempt's private artifact/cache roots. A real executable is required; fake compilers and echo wrappers cannot satisfy acceptance. This is a bounded application runner, not a pluggable arbitrary-command test framework.

## Decisions

### Independently deliverable baseline and explicit modes

Ship an ordinary Cargo baseline using pinned available Cargo/rustc first, and supported serial/native cells where admitted. Baseline A/A replay compares the same ordinary configuration in independent roots, and each side's incremental end state against its own independent clean build. Label it `baseline-replay`; it tests harness reproducibility and incremental consistency, not early-metadata equivalence. Comparing existing supported Cargo and native rails, if added, is separately labelled cross-adapter evidence and cannot replace a same-binary experimental off/on pair.

Future modes require an explicit registry entry: stable mode ID/version, exact supported flags/protocol, capability probe, toolchain identities, failure-trigger/readiness observation mechanism, compatibility restrictions, and required cells. The off/on sides use the same Cargo executable, rustc executable, sysroot and closure; only named mode-toggle inputs differ. An on side using a different patched compiler is incomparable, not a performance/equivalence result. No entry named Headstart is treated as implemented because an upstream repository exists.

The same-binary requirement applies strictly to every pipelining treatment registration. A future different-provider reference comparison is a separate qualification kind requiring its own admission, explicit provider/compiler/sysroot identities and a versioned operation-specific semantic projection with exclusions fixed before observation. It is not an off/on treatment, cannot infer raw artifact-byte equivalence, and cannot be admitted by relaxing the pipelining registry. This package defines no compiler backend integration or provider implementation; ordinary Cargo delivery is independent of such qualification and any future warm-session package.

Outcomes are `equivalent`, `mismatch`, `blocked` (required environment/tool/source capability unavailable), `unsupported` (outside the declared adapter/mode matrix), and `harness-error` (invalid inputs, bounds, capture, teardown, or observation failure). An expected real compilation failure can be equivalent; an ICE is always a failing result, even on both sides. Required blocked/unsupported/error cells prevent the requested matrix from being complete-green. An explicitly unsupported optional future cell remains visible and does not prevent shipping the fully exercised ordinary baseline. Preserve the requested matrix and required flags; never silently drop a requested row.

### Admitted compatibility matrix

Each row binds adapter, baseline/experimental mode pair, operation (`build` or `check`), host/target, profile/optimization, incremental setting, cache policy, fixture revision, features and support declarations. Do not infer support from a feature appearing in another row.

| Cell family | Initial obligation | Later admission boundary |
|---|---|---|
| Small dependency -> middle library -> application | Required ordinary Cargo build and check, cold/warm/edit/clean | Serial/native only within documented planner/source bounds |
| Real proc-macro host library + consumer | Required representative ordinary Cargo build/check row where declared toolchain supports execution | Native/experimental support must be separately declared and observed |
| Real build-script generated source/cfg + consumer | Required representative ordinary Cargo build/check row with explicit inputs | Preserve host/target, rerun facts and generated outputs; no global build-script claim |
| Thin/fat LTO consumer | Representative build rows for each LTO form selected in the admitted cohort; check is not LTO execution evidence | Explicit toolchain/linker/optimization restrictions; unsupported forms visible |
| Early-metadata body failure and metadata swap | Not initially implemented; typed unsupported without registered capability | Required for any future mode claiming early publication/swap |

At implementation admission, select and document exact representative toolchain/target/profile/LTO rows and numeric bounds; missing prerequisites in a selected required row are blocked, not skips. Baseline cells run on declared available binaries; fetching/building patched upstream compilers is not a prerequisite to baseline delivery.

### Frozen population and coverage accounting

Before execution freeze a bounded inventory, selected matrix, required flags and coverage-baseline identity. Stable role-labelled keys identify candidate cases, cell/side/step members, declared tests and planned units; do not sum unlike roles. Retain candidates excluded from selection, units outside root eligibility and every exclusion/nonroot reason rather than dropping them from the inventory. Use existing planner/compiler observations only; this does not introduce function-fragment discovery or a generic harness. Generated members must be bounded and enumerated by the predeclared manifest/expectation, not discovered only among successful outputs.

Coverage dimensions have explicit meanings: `selected` is requested membership; `eligible` is applicability under the fixed adapter/provider/operation policy; `attempted` means an owned attempt began; `executed` means the relevant real compiler/program/test invocation was observed, not necessarily successful; `restored-or-reused` means an identified complete result or retained incremental state was consumed; `unsupported` means outside declared capability; `fallback` records a separately identified admitted execution route and reason, never proof the requested route ran; `excluded` records a retained candidate or nonroot outside the declared selection/eligibility policy; `failed` records a nonpassing verdict or infrastructure outcome; `unrun` records a selected observation obligation not discharged by execution or an explicitly permitted identified reuse. Blocked prerequisites and skips retain typed reasons and requiredness, not success labels.

These are membership, eligibility, execution/reuse, route and verdict dimensions, not mutually exclusive terminal buckets: an attempted step can execute, reuse some units and fail; a fallback step can execute without covering its requested route. Define disjoint partitions only within an explicitly named dimension and role; reconcile unique member keys and allowed transitions instead of asserting that all counters add to the selected count. Keep attempt-event counts separate from unique-member coverage, so repeated retries cannot inflate coverage. Restoring source content for revert is an edit transition, not `restored-or-reused` result coverage.

Reports bind denominators and their exact member sets: selected required cell/side/step obligations for completion, expected test IDs for test coverage, and eligible unit IDs for compilation/reuse coverage, with excluded/nonroot counts and reasons alongside. State which units actually compiled versus were fresh, restored or incrementally reused; neither test success nor reused totals imply all units compiled. Optional unsupported future modes remain visible outside the independently deliverable baseline's required denominator. Correctness, then complete population/skip accounting, then latency, then footprint determine evidence review order.

Reconcile against the frozen manifest and retained coverage baseline before accepting a report. A disappeared case/unit, lost expected test, increased required skip, or changed denominator/member set is nonpassing even if replacement cases preserve or increase absolute compiled count. Required unsupported/blocked/incomplete observations stay nonpassing; an admitted fallback cannot silently count as original-route coverage. Reports cannot rewrite the baseline or use current observations to select a more favorable denominator. An intentional population revision requires separately reviewed versioned manifest/baseline admission with an explicit membership diff and reasons; it does not repair the old report or erase its regression. Keep both identities and comparison results.


### Exact private trees and replay identity

Use a fresh exclusive private invocation directory (mode 0700, no following supplied symlinks) with children for cell, side, and attempt. Source snapshots are content-equal across paired sides but never share mutable trees; artifact/target, incremental, HOME, TMPDIR, Cargo home, Mantle store/state, cache, lock, generated output and protocol roots are disjoint. Within one side, intentional incremental state carries between labelled steps only. A retry is a new attempt root and never resumes an incomplete attempt. Cold and final-clean builds use fresh artifact and incremental roots, not a deletion within a possibly shared target.

Bind source member paths/bytes, manifests/lock/config, vendor/dependency closure, compiler/Cargo content digests and version output, full sysroot/toolchain closure, linker/runtime identity, target, ordered argv, admitted child environment, features, profile, incremental/cache settings, dependency outputs, fixture/edit manifest, comparison exclusions, mode policy, and harness version into role-labelled identities. Paths for private roots may be compared through a declared root-role mapping; raw paths and transcripts remain available. Logical cell/step identity is deterministic from the manifest; random exclusive filesystem names are attempt locations, not semantic identities. Record monotonic observation sequence numbers per unit and attempt; preserve insertion/order in diagnostics, arguments, edits, and dependency facts where order is semantic. Sort only unordered manifest key sets with a documented canonical encoding, never observed message streams.

### Edit sequences that demonstrate real effects

Every edit is a checked byte-range/preimage/postimage transformation with exactly the expected match count and expected whole-tree before/after digests. Capture generated/build-script inputs as well. An unchanged step explicitly expects equal source digests. A modification expected to alter output must have an independent expected observable sentinel (e.g. numeric printed value, interface diagnostic, generated-source value), not merely equality between two potentially stale sides. Record Cargo freshness/compiler invocations or native receipts to establish rebuild/reuse. A missed edit, unobserved intended recompile, or wrong expected sentinel is a harness failure.

Required ordinary sequences include:

1. Cold compilation and executable observation for build; independent check operation with its own roots and no execution claim.
2. Warm unchanged rebuild using retained side-private state, including explicit observation of fresh/reused versus compiler-executed units. Also force an unchanged-source compiler invocation with retained incremental state through the admitted adapter's documented mechanism; if unavailable, that cell is blocked rather than represented by Cargo freshness alone.
3. Body-only change of a non-inlined dependency function; interface-compatible output change and interface-breaking/fixing changes with concrete consumer diagnostics.
4. Opaque return-type introduction and hidden-type change consumed by the next crate; generic implementation/instantiation change; const value/evaluation change; async future/body change with actual runtime polling/output where build is supported. Each gets distinct expected values/errors and postimage identities.
5. Successful base -> broken dependency body -> still broken with a further edit in another file -> repaired -> later consumer edit and subsequent edits spanning admitted structural, upstream-dependency, include-file, macro and generated/build-script-input classes -> revert to the exact base source state -> reapply the later state. Use a bounded family of campaigns where fixture/operation applicability differs; retain every required class and explicit unsupported/blocked cells. Carry the same side-private incremental state cumulatively, preserve failed-step evidence and never execute stale binaries. Source revert/reapply must include file additions/deletions, binary included bytes and generated-input identities where applicable, not just Rust text.
6. Final successful incremental state versus clean compilation of byte-identical final sources on both sides: compare status, semantic diagnostics, program behavior, and accepted output identities under a declared output policy. Record actual artifact digests. Byte equality is mandatory when the declared policy requires it; where raw compiler artifacts include admitted nonsemantic path/incremental differences, a versioned accepted-identity policy must explicitly name the exclusions and retain both raw identities. Runtime equality alone cannot claim artifact identity or reproducibility.

### Cumulative stateful campaign oracle and recovery

For every applicable step, independently materialize its declared complete source/config/input state into a fresh clean reference source and artifact/incremental tree, using the same pinned binaries and semantic policy as that side. Derive expected content from the frozen manifest, not by copying the possibly contaminated campaign tree. Verify both trees against expected identities, including absent files, included bytes and declared generated inputs; regenerate and observe outputs under the reference's private roots. This adds per-step clean comparisons to, and does not replace, the existing final-clean artifact-identity obligation. Build steps compare current executable behavior only after successful compilation; check steps compare compilation/diagnostics without inventing executable observations.

Every step has an independent expected success sentinel or real compiler-rejection/diagnostic oracle fixed before the run, as well as campaign-versus-clean comparison. Rejection requires the declared ordinary compiler exit class and structured semantic diagnostics, not any nonzero status or generic error reply. Crash, ICE, timeout, link failure, protocol failure, malformed/incomplete capture and cleanup failure are distinct nonpassing outcomes, never expected compiler rejection, including when both sides fail alike. A reference that accepts a declared broken state, or rejects it for different semantic reasons, fails the oracle; do not rewrite expected diagnostics after seeing the result.

No automatic restart, target deletion, cache reset or fresh-session fallback may conceal contamination after a broken or mismatching step. Ordinary Cargo subprocess completion between steps is not a reset of its retained incremental tree. For any future persistent session, retain session/state identity and liveness observations across steps. If an explicitly admitted recovery is necessary, record its cause, predecessor attempt/session, failed observation, exact discarded/preserved state identities, teardown and successor identity as a transition. Preserve the original failure and mark the uninterrupted-continuity obligation failed or unrun, not satisfied by post-recovery success. A source revert is not permission to reset retained state. If continuation is unsafe or impossible, stop within bounds and retain all remaining required steps as unrun/nonpassing.


### Real failure, crash, cancellation, and stale output

Trigger ordinary dependency/body and application errors with real source. Crash a selected real producer process using the process controller; cancel a running attempt through its process group/cgroup or equivalent supported process-tree containment. Capture status/signal and all descendants, then terminate and reap them, including consumers, waiters, build scripts and helper processes. Event-triggered injections require an observed exact producer/attempt event; avoid a fixed sleep as evidence that metadata was emitted. A producer that finishes before the trigger makes the injection inconclusive, never passed.

For an admitted future early-metadata mode, the source must produce a real body failure after a verified metadata-publication event, and a swap fixture must prove the consumer waited and then used the matching full metadata. Test both eventual producer success and failure/crash/cancellation after publication. With no capability to observe/control that boundary, report blocked/unsupported for that mode; ordinary baseline errors remain useful but are not renamed after-metadata cases.

Before a failed step, seed a genuine successful prior final artifact under a separately identified prior step. The current attempt may inspect it as adversarial state but cannot count its existence or execute it as current success. No failed/cancelled attempt may expose a provisional artifact/result record, signed envelope, or visibility marker as an accepted successful result. Inspect the side-private cache/store publication boundary, not a shared production cache. Complete unrelated previously successful units need not be rolled back; distinguish them by attempt/producer identity. Teardown success requires observed empty containment and bounded reap, not just the top-level child exiting.

### Structured semantic comparison, not output laundering

Retain exact stdout/stderr bytes, compiler/Cargo JSON, executable stdout/stderr, exit code or signal, process/unit/attempt mapping, artifacts, and observation/truncation metadata. Compare structured diagnostic level/code, primary message, spans under declared root mapping, child notes, suggestion applicability/replacements, and multiplicity. Preserve per-unit diagnostic and JSON event order, duplicate events, and final status. Unknown semantic fields fail closed pending policy review; malformed/incomplete JSON cannot pass as absent diagnostics.

Only explicitly versioned timing/progress records (such as Cargo Compiling/Checking/Finished, lock waits, and wall-clock fields) and unrelated cross-crate interleaving may be excluded from semantic equality. Associate records with exact units/attempts first and compare ordered per-unit sequences; cross-crate exclusions do not erase dependency-before-consumer terminal-output constraints. Do not globally sort, deduplicate, normalize all stderr, ignore all rendered diagnostics, or suppress panic/ICE text. For human-output rows preserve ordered rendered semantics per unit; if mapping is ambiguous, mark that row blocked rather than broaden exclusions. Raw excluded records remain evidence.

Fault-injection comparisons have an explicit projection: expected signal/cancellation and any consequent missing successful outputs are compared against the declared failure oracle, not a normal successful run. They still require absence of accepted provisional results and complete teardown. Timing/progress exclusions cannot erase unexpected semantic downstream errors or ordinary failure status differences.

### Bounds, environment, and failures

Admit finite maxima before running: cells, steps/cell, units/processes, source files/bytes, artifact/scratch bytes, stream bytes, diagnostic count/field sizes, edit size, per-build/per-program deadline, capability-probe deadline, total invocation deadline, and TERM-to-KILL/reap grace. Implementation must choose and validate concrete numeric values against admitted fixtures and existing child-capture conventions; this is an explicit prerequisite task, not an unbounded default. Serialize execution initially so maximum concurrent cells is 1; paired sides run in deterministic side order. Any increase requires explicit resource policy, not ambient parallelism.

Construct each child environment from an allowlist with explicit locale/timezone/config and pinned tool paths. Never set/remove process-global variables to select mode, poison RUSTC/CARGO_HOME/PATH in the parent, or rely on ambient registry/target state. No automatic network acquisition or unbounded retries. Capture overflow/deadline/ENOSPC/permission failure yields a typed nonpassing result with bounded retained evidence and process-tree cleanup; never compare truncated prefixes as complete equality. Preserve diagnostics/evidence for failed rows; cleanup removes scratch execution state only after evidence finalization and teardown, with no-follow ownership checks.

### Equivalence and time-to-error are separate reports

A semantic equivalence verdict cannot depend on wall time. Separately measure invocation-to-first-actionable-error and invocation-to-terminal-error/teardown using monotonic clocks and preserve the origin of each timestamp. Existing completion-only capture can support terminal timing; first-error timing is unavailable without a justified live observation source. Future wait diagnostics from `explain-rust-build-waits`, when present and attempt-bound, may explain producer/consumer wait intervals and first-error propagation. Their absence is labelled unavailable timing detail, not guessed zero wait or an equivalence failure. No timing comparison is a Mantle speedup claim without a separately controlled benchmark.

## Alternatives and Future Decision Record

- Rejected: require Headstart before delivering the harness. It prevents an ordinary baseline and masks unsupported capability as missing implementation.
- Rejected: use different compilers for off/on, a single shared target directory, or a global environment toggle. These confound treatment, incremental state and reproducibility.
- Rejected: copy the upstream scripts, globally sort JSON, execute any surviving binary, or use fake compiler/wiring checks. These can conceal stale success, order/multiplicity regressions, missed edits and teardown failures; license review is also unresolved.
- Selected: reuse bounded normalized Rust-plan facts and existing shell patterns; a small pure classifier with a serial bounded runner. Existing generic scheduling already handles critical pressure/resources/locality/starvation; this work does not replace it.
- Before implementing experimental registrations, record a future ADR covering mode admission, comparison/accepted-identity exclusions, private attempt ownership and failure-oracle semantics. This proposed design is not an accepted ADR and does not authorize an upstream compiler protocol.

## Risks and Verification

Compiler diagnostic JSON and artifact contents vary by pinned toolchain, so policy versions and explicit compatibility rows are maintenance obligations. Sparse fixtures can miss real compiler defects; admit representative proc-macro/build-script/LTO rows without extrapolating globally. Fault triggers can race; observation absence must remain inconclusive. Containment limitations are blockers, not permission to leave background waiters. Accepted artifact identity cannot be weakened after seeing a mismatch merely to make a row pass.

Campaign continuity and coverage baselines are additional maintenance boundaries: fixture changes can accidentally weaken a negative oracle or remove unreachable tests/nonroots while keeping compiled totals flat. Freeze expectations before the run, retain role-specific membership diffs and require separate review of population revisions. Recovery can enable further diagnostics but cannot erase a contaminated transition. Warm-session consumers must reuse these evidence contracts without making their provider or session lifecycle a prerequisite for ordinary baseline delivery.

Implementation proof runs ordinary real fixtures, checks independent expected runtime/error sentinels, repeats in fresh roots, exercises source edit mismatch and stale-artifact rejection, and observes descendants/publication state after real crash/cancel. Registering an experimental mode requires its own actually run same-binary off/on matrix, metadata-boundary success/failure/swap cases and final incremental-clean evidence. An upstream SVH panic is recorded as failure with raw evidence, not waived by turning incremental off. Retain consumer-visible regression tests for uncertain comparison/order/identity/teardown boundaries, not tests of literal source text or forwarding. This authoring package reports no implementation, test run, experimental result, speedup, release or self-hosting evidence.

Additional implementation evidence must show each cumulative step against its independently materialized clean state and predeclared oracle, including still-broken and post-repair invalidation classes, revert/reapply and visible recovery interruption. Exercise a wrong negative oracle with a clean compiler that accepts the alleged broken source, and a population regression that removes a case/test/denominator member while keeping absolute compiled count unchanged. Retain the resulting nonpassing reports and baseline identities; neither authored scenarios nor upstream reports claim those runs occurred here.
