# Cargo unit-plan contract review (2026-10-01)

Status: the opt-in two-package Cargo-unit adapter/helper and its declared offline producer are integrated in the current root. A fresh physical Mantle client imported genuine signed inputs; its initial end-to-end build timed out after producer and dependency results, and one **same-state recovery** completed the app unit and static verifier before a typed wrong-root negative. This is real bounded build-lane evidence, **not** uninterrupted cold-build success, final immutable SECOND acceptance, full Cargo compatibility, or a claim that the measured 925-unit workspace fits the 256-slice limit.

## Core and wire binding

Current production `mantle-rust-plan-core` returns ordered `ExistingUnitEffect` from `plan_existing_unit_effects(Vec<ExistingUnitFacts>)`. The effect exposes `unit_id`, `package_id`, `target_kind`, `execution_kind`, direct `dependency_unit_ids`, `arguments`, `environment`, `input_identities`, `expected_outputs`, and `execution_order`. The older origin/main `UnitEffect` API is not compatible. The pure adapter requires the current core effects and producer-supplied `PlanBindings`: logical store prefix, declared helper/rustc/toolchain/linker paths, system and declared host/target triples, sorted package source slices, direct extern bindings, metadata hash observed by rust-plan, and plan roots. These bindings are facts, **not** an authorization to inspect a host path. `input_identities` are core observations, not already-resolved store paths; producer must reconcile each against declared sources/toolchains before invoking the adapter.

The adapter serializes `mantle-plan-v2` and sorts units, slices, roots, direct inputs, and extern bindings before digesting canonical bytes. Each unit has input addressing, a store-root helper, its own source-slice input, direct dependency output inputs, and deduplicated declared tool store-root inputs (rustc and linker executable paths remain exact builder environment values). Sources use `{{mantle-source:id}}`; dependencies use `{{mantle-unit-output:id:out}}`. The rustc arguments include the rust-plan metadata hash and `--remap-path-prefix` for the own source. The helper reads `$out`, resolves direct extern artifacts and transitive `-L dependency=` search paths from declared dependency manifests, passes rustc its response file, and emits `share/mantle/unit-dependencies-v1.json` with `schema`, `direct_dependencies` (literal direct output store paths), and `artifacts`.

The producer profile is opt-in, offline, network denied, and must declare workspace source, vendor/registry sources, pinned Rust and linker toolchains, planner, and static helper. It must run Cargo metadata and Cargo unit-graph under the pinned toolchain, admit only known unit-graph versions, verify lock/vendor bindings, copy per-package source roots into producer `sources`, compute their NAR digests and source-slice facts, and publish `plan` plus an evidence record binding lock, graph, toolchain, and plan digests. A blocked producer writes evidence with blockers and no plan. There is no Cargo compilation fallback.

## Blockers and authorization boundaries

`unit-plan-build-script-run-unsupported` blocks build-script execution; `unit-plan-mode-unsupported` blocks unsupported targets, modes, unresolved externs/roots, or bad binding sets; `unit-plan-source-unsupported` blocks git and invalid source slices, entry paths, and labels; `unit-plan-triple-unsupported` blocks undeclared host/target triples; `unit-plan-host-path` blocks undeclared absolute effect paths or non-store tool bindings; `unit-plan-limit` blocks unit, source-slice, input, environment, or byte limits; `unit-plan-oracle-failure` covers Cargo/planner failure. A typed blocker prevents publishing a plan; it does not imply successful consumer admission.

## ADR 0081 review

ADR 0081's frontend/worker boundary, input addressing, direct edges, and opt-in decision still match the adapter contract. Its static plan-root consumer item 4 belongs to `bind-static-inputs-to-dynamic-plan-roots`: the same-state current-root signed positive and typed negative above exercised that shared runtime contract, but this crate does not claim ownership of it. The ADR is **not accepted** solely from those receipts: the current pinned trial predates the named-struct source refactor, its first build timed out, and immutable final-source cold/unchanged SECOND acceptance remains independently required.
