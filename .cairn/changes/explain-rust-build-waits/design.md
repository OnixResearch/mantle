## Selected Design

### Functional Core and Imperative Shell

Keep a small pure reducer adjacent to existing Rust plan types: validate identity references and event sequences, classify available intervals, normalize cohorts, and compute summaries. Inputs are normalized observations and explicit capabilities; outputs are diagnostic records and deterministic reason codes, never execution effects or cache decisions. It needs no process handles, filesystem, clocks, or network. Reuse existing identity types instead of a second Rust planner or generic event framework.

The existing application/adapter shell owns invocation identity, monotonic clock, actual process creation/reaping, dependency-ready and queue transitions where available, bounded event capture, resource collection, and sidecar publication. Extend the local adapter/session and the per-unit sandbox helper at their real effect boundaries. Default Cargo remains one ordinary sandbox build, with an opt-in wrapper/event bridge admitted as a declared tool/input inside that sandbox. The bridge forwards compiler diagnostics unchanged under the existing stream contract while separately collecting bounded typed observations; no log scraping or ambient wrapper injection. If live structured notification collection requires restructuring completion-only readers, implement it explicitly without changing compiler argv/semantic flags except the separately recorded supported diagnostic transport settings.

Record ordinary build outcome and diagnostic outcome separately. Sink failure, invalid events, or overflow marks diagnostic coverage incomplete; it does not select work, suppress compiler errors, convert a failed build to success, or authorize outputs. Collector work and memory are bounded, with a nonblocking/drop-and-mark policy rather than unbounded backpressure. Required build execution/cleanup is still performed by the existing shell independently of diagnostic success.

### Identity, Correlation, and Ordering

A run has a fresh invocation ID and one clock-domain ID; event IDs are invocation-local increasing sequence numbers. Unit identity retains the selected normalized unit ID and an opaque domain-separated digest of package/source identity, target name/kind, host and target triples, execution role, sorted/deduplicated feature set, profile, compilation mode, semantic compiler-argument/input/toolchain identities, and accepted dependency-unit edges. Render safe package labels separately from the full identity. Host build scripts/proc macros and target libraries with the same crate name are distinct. Build-script execution is not compiler execution.

An attempt key is `(invocation ID, unit identity, process role, admitted attempt number, resolved-process identity)`; retries/fallbacks retain a prior-attempt link when the execution path really has one. PIDs are short-lived correlation aids, never identities. Cache hits record the unit/cache disposition with `compiler_ran=false`, not synthetic zero-length attempts.

For default Cargo, an explicit launch/event handshake must bind each actual wrapper request to the accepted package/target/configuration and process role, including resolved arguments and invocation ID. Use Cargo's structured package/target/artifact facts and an explicit wrapper association only where they unambiguously establish that binding. A matching crate name, output basename, PID, or a nearest timestamp is insufficient. Toolchain probes are separate roles, not package compilations. Ambiguous or unavailable association is reported as unmapped; the producer may expose outer Cargo duration, but unit/wait attribution is unavailable. Choosing and verifying the supported pinned Cargo handshake is an implementation task, not an assertion that ordinary Cargo already provides it.

The collector assigns order on reception and includes source-local sequence numbers where available. Equal timestamps are ordered by sequence, never by a fabricated causal edge. Canonical report tables sort by stable unit key, role, attempt, and event sequence. Durations use integer monotonic offsets from the invocation origin; structured notifications represent receipt time with transport/source capability noted, not an assertion of exact internal compiler timestamp. No subtraction or causal merge across hosts, invocation IDs, or clock domains. Comparisons aggregate completed durations, not shared timestamp axes.

### Supported Events and Honest Wait Attribution

The minimum attempt events are launch requested, compiler/process started after actual spawn, exit observed with status/signal/timeout, and process-tree cleanup/drain complete where the shell observes it. Keep spawn failure distinct from a started compiler. Cache probes/restores and final manifest/output completion have separate kinds.

Maintain an explicit capability table for the selected toolchain and producer. Structured metadata/artifact notifications are retained only when actually emitted and supported, bound to a declared producer attempt and artifact role/opaque identity. Stable full-metadata readiness is not interface-only readiness. An output discovered after exit may be labeled completion-observed artifact, never retroactively timed metadata-ready. Cargo's terminal `compiler-artifact` message is not proof of an earlier rustc metadata event. Unsupported early-interface, body-check, wait-for-full-metadata, pause/resume, or codegen phase events are `unavailable(reason)`, not inferred from silence, process lifetime, file suffix, file mtime, or another compiler's behavior.

For each dependency edge, retain the exact prerequisite kind required by the consumer (host executable, full metadata, linkable artifact, or a future explicitly admitted interface role). A wait explanation uses only actual endpoints:

1. **Dependency wait:** observed dependent admission/request to observed satisfaction of its last required prerequisite. Identify the blocking producer attempts and prerequisite roles. If request or satisfaction is absent, retain a partial interval/unavailable duration.
2. **Ready-queue delay:** observed enqueue-as-ready to actual dispatch/start, with queue/dispatch observation coverage. Artifact-ready-to-start alone is not proof that an actual ready queue contained the consumer; label it an unattributed post-readiness gap when queue facts are absent.
3. **Artifact-ready-to-resume:** for an explicitly observed compiler pause and resume, split the pause at the latest actual readiness notification of the exact awaited producer-attempt artifacts. The first segment is awaiting artifacts; the second is post-readiness resume delay. Missing readiness or resume leaves the relevant split unavailable/censored. Never substitute resume time for unknown readiness.

Do not sum overlapping dependency waits into elapsed wall time or present an observed latest-finishing predecessor path as a proven critical path when graph/event coverage is incomplete. Report measured compiler process lifetime separately from compiler-internal active time, which may be unavailable.

### Bounds, Privacy, and Diagnostic Isolation

Use a new opt-in `mantle-rust-wait-diagnostics-v1` schema/sidecar. Do not add fields/kinds to `mantle-build-trace-v1`. Reuse its bounded validation, emit-at-real-transition, and sanitize-before-publication patterns; typed opaque identity digests are permitted schema fields, while free-form paths/digests/secrets are redacted. Never retain raw environment, argv, file contents, host paths, or raw compiler diagnostic payloads in timeline records. Use bounded safe labels, role enums, normalized digests, and redaction flags.

Initial proposed per-invocation ceilings are 4,096 unit identities, 16,384 attempts, 65,536 event/resource records, 2,048 encoded bytes per record, 256 bytes per diagnostic text field, and 16 MiB encoded sidecar total. Validate limits before allocation and while collecting; reserve space for an incomplete/overflow marker and run outcome, stop accepting optional records at exhaustion, and retain count/coverage flags without an unbounded overflow queue. Resource samples share the record/byte budgets; proposed sampling is no faster than 100 ms. An implementation task must validate these bounds on chain/wide fixtures, include identity tables and publication overhead, and document any justified adjustment before accepting the schema. Bound outstanding wrapper messages/process associations too; exhaustion yields unmapped/incomplete diagnostics, not unbounded state.

Redact before sink admission, escape controls, reject unknown versions/malformed references, and write private sidecars with the existing no-follow/private-file publication conventions. Retention is finite per run and operator-controlled across runs; the cohort ledger has a predeclared finite run count and never silently drops failures. Diagnostic values are excluded from derivation/action identities, canonical receipt preimages, signed result envelopes, cache keys, and visibility/admission rules. A sidecar may point at existing opaque identities, but no receipt hashes its timing payload.

### Repeatable Measurement Protocol

Implement a small native recipe, not a permanent third-party benchmark installation:

- A real offline chain of four local libraries plus a binary, with deterministic generated body-heavy code and a known output; and a real wide graph of eight independent local libraries plus a joining binary. Pin generation/source/lock/toolchain/fixture manifests and stay below existing source/unit admission limits. Add separate wrong-body/interface-error variants; they are failure observations, not speedup samples.
- Run the ordinary supported native local adapter/session baseline and the opt-in per-unit sandbox lane where admitted, alongside default offline Cargo. Native serial whole-unit execution is named honestly. Cargo's ordinary supported full-metadata pipelining baseline is explicitly named and is not Headstart's early-interface optimization. Compare lanes descriptively; do not call unlike planners/toolchains a causal optimization A/B.
- For each causal A/B, freeze the same rustc/Cargo binaries and closure, semantic flags, source/lock/input identities, target/profile/features, job count, CPU affinity/quota, memory limits, cache policy, diagnostic mode, and declared environment. Only the named treatment differs. Unknown/mismatched controls exclude a pair from comparable summaries with a reason; they do not delete its ledger entries. Measure instrumentation overhead in its own paired cohort, rather than confounding an optimization with collection enabled on only one side.
- Predeclare five A/B pairs per fixture, mode, and cache-state cohort, alternating AB then BA across pairs. Retain setup and warm-up outcomes, every scheduled run, invocation IDs, exit/signal/timeout, elapsed time, coverage, and exclusion reasons. Permit fewer successful pairs only with explicit counts and no blanket speedup conclusion. Report median and min/max for each successful comparable mode, paired deltas where pairs succeed, and failure/timeout counts beside them. Failed/time-limited durations remain censored outcomes, not successful elapsed samples.
- Separate clean (fresh output/state and declared cache policy), warm/cache-reuse (explicit seeded cache with disposition), and incremental (dedicated prior state plus pinned edit sequence including no-op, body edit, interface break/fix) cohorts. Declare OS page-cache controls or uncertainty; do not call a fresh target directory an OS-cold run. No-op cached units are not compiler work. Do not pool check/build or debug/release.
- Collect elapsed and CPU user/system time for the process tree or cgroup, peak memory with the chosen process-tree RSS or cgroup metric explicitly named (including RSS double-counting limitations), and peak/count-time of actually paused resident compiler processes when supported. Unsupported metrics are unavailable, never zero. Record quota/affinity, sampling interval, source and coverage; sampling peaks are observed lower bounds. Include time-to-first-error from an actual structured error observation and error-to-last-descendant-reaped drain time; completion-only stderr yields an exit-observed error bound/unavailable first-error time, not a retroactive timestamp. For timeout/cancellation, retain kill/request/reap outcomes and censored drain if cleanup is not observed.

### Content-Associated Edit Loops and Work Coverage

Extend the finite fixture/run manifest with fixed case IDs, scenario IDs, step ordinal and predecessor, a diagnostic session ID, invocation/attempt references, exact before/after content-set digests (including non-source inputs), and the expected outcome for each content version. Session association links completed durations; it does not merge invocation clocks or weaken identity/redaction rules. The same exact edit content must reach each qualified treatment and its independent expectation/clean reference. Pin reference identities and semantic observation projections; output agreement alone is not proof of complete work. Error-to-recovery steps retain both versions and failed attempts; timeout, crash and protocol failure are never expected compiler rejection.

Predeclare separate cold load/bootstrap, first edit, subsequent warm edits, no-op/unchanged, disk-result-cache hit and miss, invalidation, and error-to-recovery scenarios, retaining setup, warm-up, restore/reset and teardown outcomes. Unsupported scenarios retain their manifest cells and reason; required blocked, unsupported or incomplete cells are nonpassing, not silently narrowed to successful cases. Preserve every selected, eligible, executed, reused, fallback, excluded, failed and unrun outcome with reasons and explicit relationships between overlapping classifications. No run disappears because setup failed before an edit. Distinguish disk result restoration, resident compiler-query reuse, Cargo's ordinary incremental mode and OS page cache using separately declared state and observed dispositions, not the label “warm.” Existing Cargo/native paths can report these scenarios and unavailable resident metrics without a new warm provider or early metadata.

For provider-supported work counters record the unit of count (package/unit, query, source function, monomorphized instance, object or other declared scope), selected/eligible denominator, executed/reused/invalidated/unsupported coverage, producer and content/step/session association. Do not equate functions and instances, a fast tier and the entire build, or add overlapping work classes. Mixed-work/fallback runs expose each provider's coverage and missing population; partial fast-tier coverage cannot support a whole-build performance claim. An observed zero recompiled functions may coexist with reanalysis, resolve/define, object writing, linking and nonzero latency. Unsupported counts remain unavailable, not zero.

Publish only capability-declared, actually observed apply/invalidate/reanalyse/compile/resolve/define/object/link/runnable boundaries, with start/end semantics, attempt associations and coverage. Providers may expose combined phases or none; retain combined intervals without inventing a split, and mark absent boundaries unavailable. No human-log scraping, subtraction from elapsed time to infer active compiler work, or sum of overlapping phases. A runnable boundary requires the provider's declared completion observation; object completion alone is not runnable or permission to publish an ordinary artifact.

### Qualified Summaries and Full Session Costs

Retain bounded raw duration/resource samples and the first edit explicitly, linked to case/step/session and outcome. Predeclare a finite sample budget and distribution policy per scenario: successful comparable count, median and min/max, percentile estimator and minimum meaningful sample count (or an explicit policy to publish no percentiles). Below that threshold percentiles are unavailable, not extrapolated tail claims from five pairs. Never pool cold/bootstrap, first edit, subsequent edits, no-op, cache miss/hit or failed/censored steps; retain excluded raw outcomes and sampling gaps. Scenario-local edit latency may be reported, but cold/bootstrap, setup, warm-up and restore costs remain separately visible beside the full-session measured lifetime; a net “speedup” cannot be invented by removing them.

Memory reports name process-tree/cgroup scope and metric, sampled resident and peak values, interval, exact first/last sample offsets within each clock domain, session start/ready/idle/shutdown/reap observations and coverage gaps. Include bootstrap, compiler descendants, first/subsequent edits, idle residency and teardown in lifetime coverage; state explicitly when any region or short-lived compiler is unsampled. Idle resident footprint has a declared idle window and workload state, not an endpoint snapshot relabeled as steady state. A daemon RSS snapshot is neither a session peak nor compiler-tree memory. Sampled peaks remain lower bounds; missing compiler-memory samples and warm-up costs cannot disappear. Missing shutdown/reap leaves lifetime censored, not complete. All records obey the existing bounded diagnostic budget and authority isolation.

Order interpretation as correctness/equality qualification, complete work coverage, latency, then footprint. Ordinary descriptive Cargo/native measurements remain independently deliverable. Comparative performance requires independently established expectations/clean-reference equality for exact contents, admitted work scope and complete required population accounting; required nonpassing cells block that conclusion while preserving descriptive observations. Same-provider cold/warm is a named state treatment with identical pinned provider/binaries/configuration and only the declared state difference; it is not the strict same-binary early-interface off/on experiment. A different-backend/toolchain reference has separately admitted provider/backend/compiler/closure identities, supported semantic projections and qualification results, remains descriptive, and is never relabeled same-binary treatment or artifact-byte equivalence. The equivalence package owns qualification; this diagnostic package neither weakens its same-binary requirements nor derives correctness from timing.

No resident provider is implemented here. A future opt-in bounded warm-workspace session can emit supported observations without becoming a prerequisite for these baselines. Function fragments and resident queries remain compiler-owned scratch, not a Mantle shared fragment store, new CAS, generic scheduler, compiler-fork import or ordinary `PathInfo` promotion.

A future early-interface treatment belongs to the readiness package and must satisfy the separate equivalence package before performance is considered. It may produce real wait/resume events; this package can consume supported versions but does not require that compiler or implement the optimization.

## Alternatives Considered

- **Human-log parsing or crate-name matching:** rejected; ambiguous across features, profiles, host/target roles, repeated attempts, and concurrent dependencies.
- **File polling/mtimes or process-exit fallback for metadata readiness:** rejected as phase evidence; completion observations may be reported under their own honest semantics.
- **Extend causal trace v1 or put durations into receipts:** rejected; v1 has a different closed vocabulary and nondeterministic timings are not receipt facts.
- **Adopt Headstart's fork/scripts as a benchmark dependency:** rejected; unnecessary for ordinary baselines, unresolved license review, and known incremental panic. Concepts can be implemented natively without promising upstream results.
- **Generic event-sourced scheduler or new scheduling algorithm:** rejected; observe existing shell transitions without becoming scheduling policy.
- **Always-on instrumentation or unbounded raw logs:** rejected; opt-in bounded sanitized collection limits overhead and disclosure.

## Failures and Risks

Producer capability differences can make comparisons sparse; report coverage and unavailable fields rather than hiding gaps. A default Cargo handshake may lack sufficient supported facts on a pinned toolchain; reject unit attribution until the explicit bridge proves the mapping, while retaining the outer run outcome. Notifications observed after buffering carry receipt-time limitations. Wrapper forwarding must avoid deadlock and preserve compiler exit/diagnostics under event overflow. Missing end/reap events are unfinished attempts, not omitted rows. Sampling perturbs small fixtures and may miss peaks; record overhead/coverage and never export a memory safety guarantee. Error scheduling can change first-error order without semantic changes; timings alone cannot establish equivalence. Monotonic clocks are comparable only within one local invocation.

## Verification Plan and Non-Claims

Future implementation work exercises real chain/wide builds through the supported paths, captures actual identities/events, compares disabled/enabled outputs and existing receipt identities, deliberately overflows/redacts diagnostics, and retains body/interface errors and timeouts with drain observations. Pure reducer checks cover ambiguous identities, malformed/out-of-order events, absent endpoints, equal timestamps, overlapping waits, and incomparable cohorts. The repeated recipe is evidence only after it runs and retains manifests/results; authoring this package runs none of it.

The schema/identity/authority and cohort decisions require a future ADR task. No accepted ADR, canonical-spec update, archive, compiler/toolchain change, benchmark result, performance number, or implementation evidence is created here. Diagnostics prove only supported recorded observations, not compiler correctness, scheduler completeness, cache trust, reproducibility, release readiness, or Mantle self-hosting.
