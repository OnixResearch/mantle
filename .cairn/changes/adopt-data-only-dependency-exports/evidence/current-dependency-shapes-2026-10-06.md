## Negative findings and deferred questions

The proposed spec (`../specs/dependency-exports/spec.md:5-14,30-39,55-64,78-98`) requires bounded per-output include/library/pkg-config paths, environment defaults with output-relative placeholders, propagated dependencies, no executable dependency hooks, and a registered build-system tool/phase/option vocabulary. The current builder exposes none of those export/registry records; mantlepkgs' similarly named *producer* manifest is not that registry. Existing `Input` accepts whole-derivation and selected-output forms, and bootstrap flags mix generated/build-tree includes with dependency output paths. Whether a future native consumer needs separate host/build tools, how to select one output's record, which directories should be inferred, and which options/phases are valid are **questions for its owner**; they cannot be answered by treating these recipes as a declared adoptee.

No spec amendment is justified without the named consumer's actual contract and ownership. This review neither checks T1.1 nor T1.2, changes no Nickel/Rust interface, claims no positive/negative execution fixture, and does not authorize T2–T4 or archive. After a real first adopter is admitted under T1.1, compare its dependency/output shapes and registered options against each spec field, amend the spec if an actual gap is found, and only then reassess T1.2.
