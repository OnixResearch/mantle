# Evidence: admitted artifact export CLI seam

Date: 2026-06-02

## Scope proven

This slice adds a frontend-neutral `mantle artifact export` CLI seam around the existing pure admitted-artifact export validator.

The command accepts:

- `--artifact-ref` for a `mantle://...` artifact ref;
- `--attestation` for a frontend artifact admission attestation or admission sidecar;
- `--materialized-path` for artifact content already materialized by a Mantle storage adapter;
- `--artifact-digest`, optional `--spec-id`, `--spec-version`, and `--spec-hash` bounds;
- repeated `--content-provenance KEY=VALUE` entries;
- `--destination-mode` and optional `--receipt-out`.

The CLI does not require `/nix/store` paths, does not interpret frontend artifact kinds such as `mantle-onix-activation-closure`, and writes the same BLAKE3-bound export receipt as the pure validator.

## Non-claims

This is not yet a storage-backed fetch implementation. The CLI seam validates and receipts an already materialized artifact path; the configured Mantle storage backend/export adapter that materializes `mantle://...` refs remains open work.

This is not a deploy path. Onix cannot deploy `mantle-onix-activation-closure` through Mantle until the storage-backed export/materialization command or API exists and Onix replaces its `nix copy` path.

## Files proving the slice

- `src/artifact_cmd.rs` implements the imperative shell: JSON/path I/O, materialized-path existence check, and receipt writing.
- `src/frontend_artifact_export.rs` remains the functional core that validates admission proof, digest, provenance, destination mode, and no-hidden-fallback markers.
- `src/main.rs` exposes `mantle artifact export` without adding any Onix-specific semantics.
