# ADR 0136: Materialize consumer-hosted effect-world components

## Status

Accepted, 2026-10-29. Published checker and producer pins, genuine production,
and separately owned real Molten actor/installed-extension observations fulfill
the bounded integration gates. See
`.cairn/archive/2026-10-29-materialize-consumer-hosted-effect-components/evidence/2026-10-29-operated-consumers.json`.
This is not default consumer cutover, full local/shared parity, or release authority.

## Context

ADR 0016 gives Mantle build/materialization authority, not application hostcall
authority. A component importing an application function cannot honestly pass
standalone `wasmtime run`: only its real consumer owns that host implementation.
Replacing it with a CLI stub or treating a skipped process as successful would
misrepresent execution. Widening existing import-free Octet profiles would
silently change immutable consumer admission.

## Decision Drivers

- Preserve exact source, WIT, artifact, profile, cohort, and receipt identities.
- Retain all build-local and independent static verification.
- Leave canonical Preserves and effect admission with Molten.
- Preserve standalone-smoke defaults and immutable baseline bundle identities.

## Decision

Add an explicit `RuntimeValidation::ConsumerHostRequired` request/bundle policy.
It binds WIT package/world and exact required host imports; the bundle separately
binds exact selected WIT bytes, final component, Octet profile, runtime profile,
and immutable producer cohort. WIT bytes, not package-name metadata, bind the
package version. Contradictory standalone invocation/stdout inputs are rejected.

The producer records `consumer-host-runtime-required` as `not-run`, with no tool
or execution claims, and still executes source/lock validation, binding
generation, compilation, composition, exact import inspection, normalization,
build validation, Octet validation, materialization, and consumer remeasurement.
Non-WASI-only composition outputs are copied only after their remaining imports
match the declared virtualization plan; no WASI allowance is added.

Add `molten-component-effects-v1` to the closed toolchain selection. Obtain its
identity from Octet's source-owned admitted structural seed. Keep both baseline
profiles/defaults unchanged. Fixture bindings are generated by the pinned
wit-bindgen with declared no-stdlib helper flags, never text-rewritten. Empty
package closures retain exact checked-lock and source identities; no unused
synthetic dependency is introduced to satisfy nonempty assumptions.

The consumer must fulfill the typed runtime requirement with its real host
before activation or producing execution receipts. Structural+Bytes verification
is necessary static materialization evidence, not that fulfillment. Default
standalone policy is omitted from canonical bundle serialization so old bundles
retain their identities; consumer mode is explicitly serialized and hashed.

## Consequences

A successful producer report can truthfully mean complete static materialization
while runtime execution remains required. Consumers must inspect the verified
bundle's typed policy rather than equating materialization success with runtime
success. The checker revision/catalog constants and cohort must be repinned only
after the checker owner publishes an actual immutable revision. No temporary
revision or sibling checkout is a deliverable dependency.
