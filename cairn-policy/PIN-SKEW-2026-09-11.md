# Cairn policy vocabulary and the pinned tool revision

Recorded 2026-09-11 while draining active changes in this repository.

## Observation

`cairn validate --root .` fails before reading any change:

```
error: failed to parse policy cairn-policy/generated/cairn-policy.json:
cairn.workflow.policy.admission at schemas[3].artifacts[1].structural_admission:
unsupported structural admission: outcome_machine
```

`schemas[3].artifacts[1]` is the `outcome-machine` artifact declared in
`cairn-policy/default.ncl` (line 504: `structural_admission = "outcome_machine"`).

The failure reproduces with both tools tried:

| tool source | revision | result |
|---|---|---|
| live checkout `/home/brittonr/git/OnixResearch/cairn` | `15f0087` | rejects `outcome_machine` |
| pinned flake input `cairn` (dev-shell `cairn`) | `695124d459574ba7aeba6097310d237f393c243c` | rejects `outcome_machine` |

Evidence for the cause:

```
crates/cairn-core/src/verified/artifact_workflow/model.rs (live checkout)
  30: pub const WORKFLOW_ADMISSION_OUTCOME_MACHINE: &str = "outcome_machine";
  32: pub const OUTCOME_MACHINE_REVIEW_SCHEMA_V1: &str = "cairn.outcome-machine-review.v1";

git show 695124d45:crates/cairn-core/src/verified/artifact_workflow/model.rs
  20..28 defines proposal, delta_specs, design, tasks, markdown, acceptance,
  risk, verification, semantic_review -- no outcome_machine
```

So the live Cairn checkout is adding an admission this repository already uses
in its policy, and this repository's pinned Cairn revision still predates that
admission. The policy validator inside that pinned revision therefore rejects
the policy file wholesale.

## Consequence

- No Cairn `validate`, `gate`, `sync`, or `archive` claim for this repository
  can be produced with the pinned tool revision until the pin advances past
  the admission being added in Cairn, or until this repository stops using the
  admission.
- `nix run path:/home/brittonr/git/OnixResearch/cairn#cairn -- ...` is the
  documented day-to-day command in `AGENTS.md`, and it depends on the live
  checkout. Runs that succeeded earlier on 2026-09-11 did so because the live
  checkout was still at a revision that accepted the admission.

## Not done here

- No generated policy byte was hand-edited.
- The flake input pin was not moved: the admission is still in flight in the
  Cairn checkout, so a pin bump would point this repository at unfinished work.
- Re-mapping `outcome-machine.json` onto a supported admission is a lifecycle
  semantic decision that affects every active change and needs its own change
  package.
