# Cairn policy vocabulary and the pinned tool revision

Recorded 2026-09-11 while draining active changes; resolved by the Mantle Cairn input update on 2026-10-10.

## Historical observation

With the old pinned CLI, `cairn validate --root .` failed before reading any change:

```
error: failed to parse policy cairn-policy/generated/cairn-policy.json:
cairn.workflow.policy.admission at schemas[3].artifacts[1].structural_admission:
unsupported structural admission: outcome_machine
```

`schemas[3].artifacts[1]` is the `outcome-machine` artifact declared in
`cairn-policy/default.ncl` (line 504: `structural_admission = "outcome_machine"`).

The historical tool results and the replacement pin are:

| tool source | revision | result |
|---|---|---|
| live checkout `/home/brittonr/git/OnixResearch/cairn` | `15f0087` | rejected `outcome_machine` |
| live checkout, later the same day | after `15f0087` | accepted `outcome_machine` (`validate`: `valid: True`) |
| old pinned flake input `cairn` | `695124d459574ba7aeba6097310d237f393c243c` | rejected `outcome_machine` |
| new pinned flake input `cairn` | `007ba5193dd8fec9067a1c0e0f8ef487807af872` | includes `WORKFLOW_ADMISSION_OUTCOME_MACHINE` |

At the time, the live checkout added the admission before Mantle advanced its pinned CLI, so the old pinned tool rejected the entire policy.

Evidence for the cause:

```
crates/cairn-core/src/verified/artifact_workflow/model.rs (live checkout)
  30: pub const WORKFLOW_ADMISSION_OUTCOME_MACHINE: &str = "outcome_machine";
  32: pub const OUTCOME_MACHINE_REVIEW_SCHEMA_V1: &str = "cairn.outcome-machine-review.v1";

git show 695124d45:crates/cairn-core/src/verified/artifact_workflow/model.rs
  20..28 defines proposal, delta_specs, design, tasks, markdown, acceptance,
  risk, verification, semantic_review -- no outcome_machine
```

The old pinned revision predates an admission this repository already uses in
its policy. That tool could not validate the policy file or gate any change.

## Resolution

`flake.nix` and `flake.lock` now select the published Cairn GitHub `main`
revision `007ba5193dd8fec9067a1c0e0f8ef487807af872`. Its NAR hash is
`sha256-Kgx8JgsC/+26ETbL3lRaxXAYfzv2cmtG/i9OywPOz0c=`, identical when
prefetched through GitHub and through the local Git mirror. The root lock graph
was regenerated by Nix for Cairn's new transitive inputs; only Cairn's locked
source metadata was normalized to the directly prefetched GitHub revision.
The pinned tool has the checked-in `outcome_machine` admission; no policy
mapping or generated policy byte was changed.

GitHub `origin/main` was confirmed to name that revision. On Leviathan, private
Git input authentication is unavailable, so checks use exact-revision local
mirrors with the locked NAR hashes. That host-specific fetch substitution
does not change the committed input URLs or establish release readiness.
The earlier Rust-plan evidence records checks with the same Cairn revision
from the live checkout, before the pinned tool was updated.

## Validated pinned-tool consumption

On Leviathan, `nix develop . --no-write-lock-file` with exact-NAR local
overrides for seven Git input fetches unavailable directly on that host placed
`/nix/store/1z6bhr2cl43z4kpsvjkxy9b47nqr9pkg-cairn-0.1.0/bin/cairn`
on `PATH`. From the Mantle repository root, that pinned CLI returned
`valid: true` for `cairn validate --root .` and `valid: true`,
`verdict: PASS` for proposal, design, and tasks gates on
`separate-rust-plan-hexagon`; the tasks gate reported no ready tasks.
The Leviathan run log `mantle-cairn-pin-007ba-cli-gates-corrected-20261010.log`
has BLAKE3 identity `d615f47e2a866f7aa5974054cbf500d573526e0f6a1ba08eb51f0762c35e0552`.
The host fetch overrides change only source retrieval; the checked-in
`flake.lock` retains the published GitHub source and its exact NAR hash.

The operator lifecycle command and repo-owned evidence runner now resolve
`cairn` from the pinned dev shell instead of a sibling checkout. The runner's
self-test passed, and a non-mutating Rust-plan dry-run selected `cairn: cairn`
without executing commands, syncing specs, or archiving. The Leviathan run log
`mantle-cairn-pin-007ba-lifecycle-runner-smoke-20261010.log` has BLAKE3
identity `ed8a3e5b1e2d8411b05c43caf5443a57d1c8a4f3df90f8e01ba47147fce26c82`.

This restores pinned lifecycle admission, not release-readiness compatibility
for every historical fixture. The pinned CLI rejected the checked-in
function-address Valence/Kamacite sample receipts; their input-contract
findings and producer-owned adoption path are recorded in
`docs/function-address-release-binding.md`.

Mantle also aligned Crane's root `cargo test` phase with the existing

to the changed flake files, the focused adoption and root package checks

then completed `all checks passed!`, including 6,262 nextest passes and 150

and is not a release, archive, or function-address readiness claim.
