# Prebuilt Android source admission

The APK adapter's reviewed Linux x86_64 metadata cohort lives at `android.reviewed` in `lib/android.ncl` (`AndroidReviewedSources` from `lib/lib.ncl`). Its data owner is the checked-in `mantle-android-prebuilt-sources-v1` manifest, not the published Android source cohort governed by [ADR 0089](../adr/0089-admit-prebuilt-android-toolchain-through-fixed-output-sources.md). The reviewed seven-field metadata preimage is the UTF-8 JSON rendering of `["mantle-android-prebuilt-record-v1", component, version, URL, hexadecimal SHA-256, archive kind, archive root, platform]`; `record_identity_blake3` is excluded from its own BLAKE3 preimage. **These reviewed metadata digests are not ADR 0089 source-v1 identities**: the published `AndroidSources.cohort` uses `mantle-android-source-v1\n` plus a compact six-field array and SRI SHA-256, so the same archive has a different identity in the two explicitly separate domains. Never use the reviewed digest as a published source-v1 record identity or evidence of upstream binary provenance. Neither domain extends the source-built bootstrap chain. Nickel 1.17 cannot calculate BLAKE3: `cargo test -p mantle --test android_sources reviewed_cohort_identity_is_blake3_of_normalized_metadata` recomputes every reviewed digest from Nickel's canonical string. A normal Nickel evaluation only checks the manifest's declared metadata.

Component labels are lowercase ASCII letters followed by lowercase letters,
digits, or hyphens (at most 48 characters). Versions start with a digit and
contain only ASCII letters, digits, `.`, `+`, `_`, and `-` (at most 64
characters). Archive roots end in `/`, comprise nonempty relative
alphanumeric-leading segments with `.`, `_`, `+`, and `-` permitted thereafter,
and are limited to 256 characters; `.`/`..`, empty segments, absolute paths,
and backslashes are rejected.


Use `AndroidReviewedSources.reviewed_source "temurin-jdk"` to select a pinned reviewed metadata record and `AndroidReviewedSources.fetch_source` to lower a flat SHA-256 fixed-output fetch (fetching alone grants no tool authority). For a native tool consumer, `AndroidReviewedSources.bind_tool "temurin-jdk" admitted_record consumer_derivation` validates the reviewed URL, version, hex SHA-256, layout, platform and metadata BLAKE3, then checks the **finite reviewed-to-published alias table** against ADR 0089's canonical record: published version, URL, root, platform and the explicitly pinned equivalent SRI SHA-256. The table covers `temurin-jdk`/`jdk`, `android-cmdline-tools`/`sdk-commandline-tools`, `android-build-tools`/`build-tools`, and `android-platform`/`platform-android-jar` (the last maps reviewed `35_r02` to published `35-r02`). The binder calls published `validate_record` and `bind` before adding reviewed-only metadata to the consumer; the resulting single executable fetch input is the canonical published source-v1 fetch, not a second reviewed archive. The reviewed digest never substitutes for source-v1 admission, and fixed-output SHA-256 independently refuses downloaded byte drift.

A source bundle exported from the reviewed fetch derivation can be imported and pinned, then replayed with `build --offline-source-preflight --no-substitute`. `tests/android_sources.rs` uses a real `file:///` fixture and removes its original payload before offline replay; its unmatched URL case refuses the request at preflight. Offline readiness proves availability of the requested bytes, not an Android tool run. Archive admission does not unpack, execute or test JDK/SDK binaries and proves neither binary provenance nor license eligibility, malware absence, compiler correctness, APK behavior, reproducibility or release eligibility. ADR 0089 governs the separate published source-v1 cohort and does not assign its source identities to this reviewed metadata manifest.

A historical isolated proof fetched the reviewed build-tools 35.0.0 archive through its original HTTPS URL, imported and pinned the source bundle, verified locally signed fetched PathInfo/NAR, and used the then-top-level `android.bind_tool` consumer to copy the actual archive to a byte-identical output. Current authoring uses `android.reviewed.bind_tool`; the historical receipt predates this namespace cutover and does not demonstrate the current expression. It proves neither SDK executable use nor a signed APK. The preserved command/output receipt is `.cairn/changes/adopt-android-prebuilt-toolchain-sources/evidence/implementation-2026-09-30.md`.
