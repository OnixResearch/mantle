# Prebuilt Android source admission

The reviewed Linux x86_64 source cohort is `lib/android.ncl`; the typed admission and binder API is `lib/android/sources.ncl`, exported as `AndroidSources` from `lib/lib.ncl`. This cohort does **not** extend the source-built bootstrap chain. Its first-party metadata identity is BLAKE3 over the UTF-8 JSON rendering of this ordered array: `["mantle-android-prebuilt-record-v1", component, version, URL, SHA-256, archive kind, archive root, platform]`. The `record_identity_blake3` field is excluded from its own preimage. Nickel 1.17 cannot calculate BLAKE3: `cargo test -p mantle --test android_sources reviewed_cohort_identity_is_blake3_of_normalized_metadata` recomputes every reviewed identity from Nickel's canonical string. Run this freshness rail before accepting a manifest change; a normal Nickel evaluation compares checked-in metadata but does not independently recompute its BLAKE3 digest at runtime.

Component labels are lowercase ASCII letters followed by lowercase letters,
digits, or hyphens (at most 48 characters). Versions start with a digit and
contain only ASCII letters, digits, `.`, `+`, `_`, and `-` (at most 64
characters). Archive roots end in `/`, comprise nonempty relative
alphanumeric-leading segments with `.`, `_`, `+`, and `-` permitted thereafter,

Use `AndroidSources.reviewed_source "temurin-jdk"` to select a pinned source, `fetch_source` to lower it to a flat SHA-256 fixed-output `builtin:fetchurl`, and `bind_tool "temurin-jdk" admitted_record consumer_derivation` to add its fetch derivation as an input and put the reviewed component, SHA-256, and BLAKE3 metadata identity into the consumer's environment. The binder selects the expected record from the reviewed cohort itself, not from the caller; it refuses a changed URL, version, SHA-256, layout, platform, component, or BLAKE3 string before it returns a consumer. The fetcher's fixed-output SHA-256 refuses downloaded byte drift before a consumer executes. `bind_tool` only yields a native sandbox derivation; this is an Android adapter convention, not a global ban on unrelated hand-authored derivations.

A source bundle exported from this derivation can be imported and pinned, then replayed with `build --offline-source-preflight --no-substitute`. `tests/android_sources.rs` uses a real `file:///` fixture and removes its original payload before offline replay; its unmatched URL case refuses the request at preflight. Offline readiness proves source identity and availability, not an Android tool run. Archive admission does not unpack, execute, or test the JDK or SDK and proves neither binary provenance nor license eligibility, malware absence, compiler correctness, APK behavior, reproducibility, or release eligibility. See [ADR 0087](../adr/0087-admit-prebuilt-android-toolchain-through-fixed-output-sources.md).

A scoped isolated proof additionally fetched the reviewed build-tools 35.0.0 archive through its original HTTPS URL, imported and pinned the resulting source bundle, verified the local signed fetched PathInfo/NAR, and used `android.bind_tool` in a native sandbox consumer to copy the actual fetched archive to a byte-identical output. This proves that one reviewed fixed-output source resolves to a physical consumer input; it does not run `aapt2`, `d8`, `apksigner`, or any JDK/SDK executable, and it does not prove the other cohort members or a signed APK. The exact command/output receipt is `.cairn/changes/adopt-android-prebuilt-toolchain-sources/evidence/implementation-2026-09-30.md`.
