# Android APK adapter (offline, staged)

The APK adapter does not run Gradle or download dependencies. `crunch-android-core` validates a bounded typed plan without I/O, and `crunch-android` binds independently reviewed prebuilt source records to fixed-output archives. The authored plan is not itself the reviewed source authority: pass the expected build-tools, Temurin JDK, and Android platform records from `android.reviewed_source`, not copies taken from the plan. Each admitted archive is checked against the reviewed record and its SHA-256 before any execution. The manifest, resource and Java members must exist as regular, non-symlink files beneath the declared source tree; signing requires explicit keystore and password-file inputs. Do not import the user's `HOME`, `ANDROID_HOME`, SDK installation, or signing config.

Author APK plans with `let android = import "android.ncl" in android.mkApk { module = "demo", application_id = "org.example.demo", version_code = 1, manifest_member = "AndroidManifest.xml", resources = ["res/values/strings.xml"], java_sources = ["src/Demo.java"] }`. The Nickel contract supplies only the reviewed build-tools 35.0.0, Temurin 17.0.17+10, and Android platform 35_r02 identities and the fixed ZIP epoch unless explicitly supplied matching reviewed records/policy. It rejects unsafe source members, metadata drift, unsupported signing schemes, and missing source sets before fetch or execution. `android.fetch_toolchain` constructs the three independently pinned FOD fetch derivations; evaluating `mkApk` itself only produces the typed plan. Pass that plan and separately admitted archive paths into the Rust adapter to generate and run the derivation steps. An explicitly signed plan names only a relative keystore member and scheme set; its password file is supplied separately to the signing derivation, never embedded in the plan.

One deterministic extraction derivation per archive rechecks SHA-256 and extracts into its output. The source archive and statically linked busybox-style utility must both be declared store inputs. The *same-run* trust boundary uses the real builder's noncached `BuildOutcome` for each exact converted extraction `.drv`, and reads independently trusted FOD/utility/output PathInfo from `crunch-store::OutputLookup` before admitting extracted trees. PathInfo's `deriver` field is **not signed** and cannot establish execution provenance on its own. Reject cache/fresh-process reuse until a signed derivation binding or independently recomputed extracted content can establish that edge. The shell-only stub test proves executable argv, environment, ordering, and input wiring; it does not replace the store-backed proof.

Tool stages are separate derivations: `aapt2 compile`, `aapt2 link` (manifest/application ID/version code), `javac`, `d8`, `jar` update then `zipalign`, and optional `apksigner`. A build with no signing configuration ends at `unsigned.apk`. Every stage pins `SOURCE_DATE_EPOCH`, `LC_ALL=C`, `TZ=UTC`, JVM locale/timezone/encoding options and sorted source/class/resource order. The `jar` update stamps its DEX entry from the fixed epoch before zip alignment. The keystore and password file are declared only on the signing stage. A source-record identity is the BLAKE3 digest of canonical *metadata*, not an archive-content digest; the archive SHA-256 and store trust are separate checks.

The offline real-builder fixture uses static BusyBox 1.37.0 from `/nix/store/8mf4s8c4xjvlkj12p299qylrb30g7zzh-busybox-static-x86_64-unknown-linux-musl-1.37.0/bin/busybox` (or an explicitly configured `SNIX_BUILD_SANDBOX_SHELL`) as a signed, symlink-free store tree member named `busybox`; its parent store object is a declared dependency. Three local `file://` fixture archives have their exact SHA-256 fixed-output derivations built through `FetchBuildService`. The ordinary `BubblewrapBuildService` then realizes extraction and five unsigned APK steps. The fixture rejects swapped extraction outcomes, missing trust keys, and cached outcomes before any SDK stub runs. Stub SDK scripts produce `unsigned.apk`; no upstream SDK binary, official APK installability, or network access is claimed.

Content-addressed output paths are unknown until each stage is realized. A consumer must realize the extraction derivations, verify the same-run outcomes against the configured store keys, and then realize APK stages in order, providing already-verified output paths from earlier stages. There is no guessed store path and no caller-supplied extracted tool tree. The source admission and real-SDK build proofs are separate changes. A successful offline stub run says nothing about an official APK's installability, behavior, byte-for-byte reproducibility, or release eligibility.

Official Google build-tools and Temurin binaries are dynamically linked: the reviewed `aapt2` requests `/lib64/ld-linux-x86-64.so.2`, while the builder mounts no host `/lib64`. The adapter instead binds separately reviewed glibc/libgcc source cohorts by full-tree NAR SHA-256 and signed PathInfo before SDK execution. Both complete store objects enter **every** SDK derivation; its command script explicitly invokes the declared glibc loader with a declared-library search path for `aapt2`, `javac`, `d8`, `jar`, `zipalign`, and `apksigner`. Do not bind the host root, `/lib64`, or an ambient `/nix/store` path into the sandbox. The separately tracked official-build rail checks these actual binaries; the stub fixture above does not.

For the separately tracked signed Java example, reserve at least 16 GiB of free scratch space for two fresh store/state pairs and one perturbed rebuild; the adapter's fixed-output archive guard permits at most 2 GiB per archive. A connected original-HTTPS fetch or a matching prefetched source bundle is required before the offline `SourceFetchOverridePlan` replay. The sandbox needs user namespaces, Bubblewrap, a declared static shell/utility, and signed store admission of the runtime loader, its shared libraries, the reviewed SDK/JDK/platform archives, source tree, and separately held signing materials. If any prerequisite or verifier is absent, record a blocker and produce no success receipt. No APK proof is a device/emulator install, launch, or runtime-behavior claim.

The runner sets `TMPDIR` to its private spacious run directory before entering the pinned Nix devshell; that shell creates a temporary Crane-vendored Cargo home there, rather than relying on the host `/tmp` or opt-in repository `vendor-deps/`. Its Cargo target is separately private and outside the read-only source snapshot.

Run `scripts/prove-android-apk.py --help` for the reviewed-archive and private-target arguments; launch the resulting command **detached with pueue**, capture its full task output, and preserve its scratch run directory. The rail imports or connects to the three original-HTTPS SDK/JDK archives, proves their pinned offline `SourceFetchOverridePlan` replay, exports `examples/android-minimal.ncl`, generates one **test-only** keystore, and runs an ignored real-Bubblewrap proof in three independent store/state directories. It writes a checked-in success receipt only after APK structure, reviewed `apksigner verify`, a signed-region tamper rejection, two identical BLAKE3 digests and a changed-Java digest are all observed. On any missing prerequisite or mismatch it writes `evidence/official-build-blocker.json` and no new success receipt. Private production signing keys must never be placed in a content-addressed store.

The official rail MUST run from a separately materialized, read-only full-source snapshot, not a shared root while other owners edit `crunch-build` or `Cargo.lock`. Capture only after `BACKEND TEST SNAPSHOT DONE`, CA final source-ready, the backend's one serialized manifest/lock/vendor transaction with stable lock, and the S0 B2/root integrator second-source stability barrier. Then `scripts/snapshot-android-apk-source.py --source . --snapshot <fresh-scratch-source> --manifest <scratch-manifest.json>` copies tracked edits and untracked owner source files with per-file BLAKE3 and pre/post mode/content checks. It rejects escaping symlinks and active vendored-source replacement rather than silently omitting an ignored dependency. The canonical source-profile BLAKE3 and manifest BLAKE3 are Mantle's content identities; the additionally printed NAR SHA-256 is **only** the Nix tree-interoperability check. Invoke the proof script **from the copied script in that snapshot**, passing `--evidence-dir <original-change-evidence-directory>`, `--source-snapshot-manifest`, `--expected-source-profile-blake3`, `--expected-source-manifest-blake3`, `--expected-source-nar-sha256`, and `--expected-mantle-sha256`. The first Mantle binary and prefetched source bundle are separately pinned; use `--expected-bundle-blake3` for a prefetched bundle. The rail rechecks the source tree, manifest, binary and bundle after actual SDK verification and refuses a success receipt on drift.

The proof rehashes every included source member, including `Cargo.lock` and the APK, build and store owner crates, by BLAKE3 before and after compilation. Ignored `vendor-deps/` is recorded as excluded only because the proof Cargo command uses `--offline` without opt-in `.cargo/vendor-config.toml`, and the active `.cargo/config.toml` does not replace registry sources; an active replacement fails snapshot capture, and any needed omitted dependency fails the proof with a blocker rather than being silently treated as verified. NAR SHA-256 never substitutes for these Mantle-owned source identities.

The signed example enables only APK Signature Scheme v2 and declares Android `minSdkVersion="24"`, the first API level supporting that scheme; the proof keystore is not a release credential.
