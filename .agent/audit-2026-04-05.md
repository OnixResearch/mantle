# Crunch Audit — 2026-04-05

Focused audit of crunch-owned code (~15k lines). Vendored snix/fuse
crates excluded except where they interface with crunch.

## Critical

### 1. Tar extraction: no path traversal validation

`fetcher.rs:extract_tar()` joins the entry path directly onto the output
directory without checking for `..` components:

```rust
let dest = out_path.join(&relative);  // line ~454
```

A malicious tarball with entries like `../../etc/cron.d/evil` would write
outside the output directory. The `strip_prefix` logic only removes the
top-level component — it doesn't sanitize `..` in deeper components.

**Fix**: After computing `dest`, canonicalize and verify it starts with
`out_path`. Or reject entries containing `..` components.

**Severity**: Critical in a build system — fetched tarballs come from the
network and the URL is user-specified. The FOD hash check mitigates this
(the attacker would need to know the hash), but `--fix` mode and dummy
hashes bypass verification.

### 2. Tar extraction: symlink escape

`extract_tar()` creates symlinks without validating the target:

```rust
std::os::unix::fs::symlink(target.as_ref(), &dest)?;
```

A tarball can create a symlink `foo -> /etc/passwd` then a regular file
`foo/evil` which follows the symlink and writes to `/etc/passwd/evil`.
Or more directly: symlink `../../etc/cron.d` then write files "through"
it.

**Fix**: Validate symlink targets are relative and don't escape the
output directory. Or resolve all paths after extraction and reject
escapes.

## High

### 3. Temp directory `/tmp/crunch-builds` never cleaned

`main.rs` creates `/tmp/crunch-builds/` for bwrap sandbox workdirs but
never cleans them up. Each build creates a UUID-named subdirectory with
FUSE mounts, build scratch space, and output directories. Over time this
fills `/tmp`.

```rust
let workdir = std::env::temp_dir().join("crunch-builds");
std::fs::create_dir_all(&workdir)
```

No cleanup on success or failure. The bwrap sandbox may unmount FUSE but
doesn't remove the workdir.

**Fix**: Remove the build-specific subdirectory after `finish_build`.
Add a cleanup-on-startup for stale workdirs from crashed previous runs.

### 4. `orchestrate.rs:566-567` — double unwrap on output lookup

```rust
let build_output = build_result.outputs
    .get(intermediates.iter().position(|x| x.name == intermediate.name).unwrap())
    .unwrap();
```

If `intermediate.name` doesn't match any entry in `intermediates` (logic
bug in the caller), this panics. In a multi-output CA build, this is the
path between pass 1 and pass 2. A mismatch means corrupted intermediate
state.

**Fix**: Return `Error::Internal` with context about which output name
was missing and which were available.

### 5. Fetcher downloads have no timeout

`fetch_flat()` uses `ureq::get(url).call()` with no timeout
configuration. A slow or malicious server can hang the build indefinitely.
The `MAX_DOWNLOAD_BYTES` limit exists but applies after the connection is
established.

**Fix**: Set `ureq::AgentBuilder::timeout()` (connect + read). 60s
connect, 300s total is reasonable for large tarballs.

## Medium

### 6. `main.rs:772` — unwrap on `query` after early return guard

```rust
let query = query.unwrap();
```

This is guarded by an early return on `query.is_none()` a few lines
above, but the compiler can't prove it. If the guard is ever refactored
away, this panics.

**Fix**: Use `let Some(query) = query else { ... }` pattern.

### 7. Worker `expect()` calls (3 sites)

- `worker.rs:211` — `get_mut(key).expect("goal must exist")`
- `worker.rs:586` — `get_mut(awaiting_key).expect("awaiting goal must exist")`
- `worker.rs:688` — `get_mut(&drv_key).expect("just checked")`

All are internal invariants — the key was just inserted or verified. But
`expect()` in async code produces unhelpful panic messages without the
drv key. If any of these fire, the entire build pipeline crashes.

**Fix**: Return `Error::Internal(format!("...key={key}..."))` instead.

### 8. TOCTOU in source path validation

`orchestrate.rs` checks `PathBuf::from(&abs).exists()` for source
inputs, then later ingests the path. Between the check and the ingest,
the path could be deleted (GC, user error). The ingest would then fail
with an opaque castore error instead of the clear "source input not
found" message.

Low risk in practice (GC during build is unlikely), but the error path
is confusing.

### 9. `ca_mapping.rs` — silently ignores save failures

```rust
pub fn save(&self, state_dir: &Path) { ... }
```

Write errors to the CA mapping JSON file are silently ignored (the
function returns `()`). A full disk or permission error loses the
mapping silently, causing unnecessary rebuilds on next run.

**Fix**: Return `Result` or at least `tracing::warn!` on failure.

### 10. Build log directory creation failures ignored

`main.rs`:
```rust
let _ = std::fs::create_dir_all(&log_dir);
```

If the log directory can't be created (permissions, full disk), logs are
silently lost. Not a correctness issue, but makes debugging impossible.

## Low

### 11. `crunch-builds` workdir path is predictable

`/tmp/crunch-builds/{uuid}` uses UUIDv4 which is random, but the
parent path is fixed and world-readable. Another user could create
`/tmp/crunch-builds` as a symlink before crunch runs, redirecting
all build workdirs. `create_dir_all` follows symlinks.

**Fix**: Use `tempfile::tempdir_in()` or verify `/tmp/crunch-builds`
is owned by the current user after creation.

### 12. `find_git` PATH scanning trusts arbitrary directories

`find_git()` scans PATH and returns the first `git` binary found. If
PATH contains a malicious directory with a trojan `git`, it's used for
`fetchGit` operations.

Low risk — if the user's PATH is compromised, they have bigger problems.

### 13. Nickel eval errors not sanitized for terminal

Nickel evaluation errors may contain ANSI escape sequences or control
characters from user-supplied `.ncl` files. These are printed directly
to stderr. A malicious `.ncl` file could inject terminal control
sequences.

## Positive Observations

- Tiger Style limits are pervasive: `MAX_TAR_ENTRIES`, `MAX_DOWNLOAD_BYTES`,
  `MAX_RECURSION_DEPTH`, `MAX_BUILD_DEPTH`, `MAX_EXPORT_DEPTH`, `MAX_GOALS`,
  `MAX_IN_FLIGHT`.
- Saturating arithmetic used consistently (`saturating_add`).
- FCIS boundary clean: `goal.rs` is pure (no I/O), `worker.rs` is the shell.
- FOD hash verification catches tampered downloads.
- CA marker fix (blake3) is correct — avoids the zero-padding collision class.
- No `unsafe` in crunch-owned code.
- No `todo!()` or `unimplemented!()` in production paths.
- `debug_assert!` used for internal invariants (doesn't fire in release).
