# Nario v2 format-boundary review

## Goal

Define bounded Nario v2 read compatibility without promoting a transport archive into a package recipe or trust grant.

## Selected boundary

Mantle will pin an exact Determinate Nix producer revision and support list and import for that version only.

The parser will also support exact foreign source preparation when an admitted plan names the original Nix source path.

Nario export remains unsupported in this change.

## Rejected claims

- The announcement article is not a complete binary format specification.
- Nario does not replace concrete derivation graph export.
- A valid original Nix signature does not authorize a recomputed Mantle target path.
- An arbitrary built output cannot become a source record through relabeling.
- Successful parsing does not prove trust, package correctness, reproducibility, or release eligibility.

## Required audit risks

- Format drift after the pinned producer revision.
- Unsupported mandatory metadata and content-addressed variants.
- Large payloads, non-seekable input, record limits, and truncation.
- Duplicate paths, conflicting metadata, wrong prefixes, and signature policy.
- Unsafe NAR filesystem entries during source projection.
- Partial store visibility after a later archive failure.

## External evidence

- Determinate Systems, “Changelog: introducing `nix nario`,” published 2025-10-31: <https://determinate.systems/blog/changelog-determinate-nix-3120/>.
- The article identifies Nario v2 as a metadata-first sequence of NAR payloads with signatures and content-addressed path support.
- Exact compatibility still requires pinned source and generated byte fixtures.

## Validation state

The implementation claims read compatibility only for the pinned v2 boundary. It supports
bounded list and import operations. Export remains unsupported. The source-projection path
requires exact admitted original paths and emits separate target-identity evidence.
