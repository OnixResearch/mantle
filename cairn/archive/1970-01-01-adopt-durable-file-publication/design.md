# Design: durable file publication adoption

## Completion contract

The change is complete when Mantle consumes the exact reviewed Radicle revision through aligned Cargo and Nix identities, immutable segment and anchor publication uses one caller-opened parent capability, every shared mechanical disposition has an explicit Mantle interpretation, the existing adapter remains available for rollback, the shared corpus and Linux integration tests pass, and Cairn and Nix validation accept the archived change.

False completion includes a sibling-path dependency, an RID without an exact revision, evidence without executable adoption, use for replaceable manifests or directory bundles, check-then-rename no-replace, a no-op parent synchronization, loss of cleanup state, or treating `CommittedDurabilityUnknown` as either uncommitted failure or durable success.

## Portfolio frame

The exact goal is a bounded consumer adoption for immutable remote-attempt objects. Observable evidence is source-lock agreement, adapter tests, all 17 shared corpus rows, Linux filesystem tests, typed evidence, focused traceability, and repository validation.

Audit risks are source substitution, lock drift, parent-path substitution, outcome collapse, cleanup loss, incorrect existing-content interpretation, authority transfer, silent fallback, and unsupported platform claims.

The source budget is the reviewed producer revision, its archive, Mantle's accepted pilot, and current Mantle implementation. The retrieval budget is eight focused source or contract files. The review budget is two correlated local passes and one advisory model pass. The validation budget is focused Cargo, Nickel, Nix, Cairn, and one full flake check. Allowed final outcomes are validated, blocked with an exact source or tool failure, or exhausted with the strongest checked result.

The advisory audit reinforced no-follow parent opening, no-replace enforcement, and explicit rollback checks. It mislabeled `CommittedDurabilityUnknown` as uncommitted and proposed unrelated HTTP status tests. Those suggestions are rejected against the producer API and Mantle boundary.

## Functional core and imperative shell

`durable-file-publication` owns request admission, phase classification, and the capability-relative mechanical shell. Mantle owns a pure mapping from shared dispositions to product outcomes. Mantle's thin adapter opens and authorizes the parent, supplies bounded stage names, invokes the shared shell, and compares existing bytes after `DestinationExists`.

The shared request uses the exact destination leaf, payload byte count, caller-selected maximum, mode `0600`, bounded collision attempts, `NoReplace`, and `DurabilityRequired`. The parent is opened with no-follow directory semantics before the shared shell runs.

## Outcome mapping

- `CommittedAndParentSynchronized` means the immutable object was created with the requested durability observation.
- `DestinationExists` triggers Mantle's bounded no-follow read. Exact bytes are idempotent; different bytes are an immutable conflict.
- `CommittedDurabilityUnknown` returns a distinct committed-but-not-proven-durable result. It never triggers cleanup or automatic rollback.
- `NotCommitted` retains the exact primary failure and cleanup disposition.
- Invalid request or observation streams remain internal contract failures and cannot become product success.

## Product ownership and rollback

Mantle retains object identity, byte limits, canonical JSON, existing-content equivalence, manifest replacement, chain validation, retention, deletion, receipts, diagnostics, and retry policy. The dependency grants no build, cache, release, deployment, retention, garbage-collection, or deletion authority.

The current local publisher remains as an explicit backend for rollback. Production selects the shared backend directly. There is no ambient environment switch and no automatic fallback after a shared-path failure.

## Source and platform boundary

Cargo and Nix use `https://git.onix.computer/z3tAR4For7qw8ZirkJzoDw1VNDDLM.git` at revision `951c27f59003cea9bfdb40ed4d89653d50fada1f`. The RID and revision remain distinct facts. GitHub and sibling paths are forbidden executable sources.

Linux execution can establish the selected filesystem behavior. Android compilation or producer evidence does not establish Mantle Android execution. Other operating systems remain unsupported for this adoption.
